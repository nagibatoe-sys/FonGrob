# Развёртывание сервера ФОНГРОБ

Состав — Node.js, PostgreSQL 17, Supabase Auth, PostgREST и Caddy с автоматическим HTTPS. База и служебные API доступны внутри Docker-сети. Приложение дополнительно доступно оператору на loopback-порту 3000.

Нужны Docker Engine с Compose v2, Python 3 и домен с DNS-записями на VPS. Перед установкой проверьте действующие службы и занятые порты. На VPS с работающим системным Caddy не запускайте сервис `proxy` из Compose.

## Первая установка

Из корня проекта выполните `python3 deploy/prepare.py` только при отсутствии `deploy/.env`. Скрипт создаёт файл один раз и генерирует три отдельных секрета. Заполните DOMAIN и PUBLIC_URL. PUBLIC_URL должен быть https://ваш-домен. SMTP не нужен: пользователи создаются администратором. При обновлении сохраняйте существующий `.env`.

```
docker compose --env-file deploy/.env -f deploy/compose.yml up -d --build db auth rest app
python3 deploy/migrate.py
docker compose --env-file deploy/.env -f deploy/compose.yml up -d season_worker
python3 deploy/create-user.py admin --name 'Администратор' --super-admin
```

Команда создания пользователя запрашивает пароль скрытым вводом. Для остальных учётных записей используйте `python3 deploy/create-user.py логин --name 'Имя'`. Логин: 3–32 латинских символа, цифры, точка, дефис или подчёркивание; пароль: минимум 5 символов. Публичная регистрация и восстановление пароля по почте отключены. Пароль меняет оператор командой `python3 deploy/reset-password.py логин`.

Если Caddy уже запущен как системная служба, добавьте отдельный сайт `fongrob.89-125-34-144.sslip.io { reverse_proxy 127.0.0.1:3000 }`, проверьте конфигурацию и перезагрузите Caddy. Затем проверьте `curl --fail https://fongrob.89-125-34-144.sslip.io/api/health`. Существующие сайты в `/etc/caddy` сохраняйте. Если системного Caddy нет, можно запустить Compose-сервис `proxy` профилем `https`.

Мигратор ждёт таблицы Supabase Auth, применяет SQL по порядку и фиксирует контрольные суммы. Повторный запуск пропускает выполненные миграции. Изменённая применённая миграция останавливает выполнение. Демонстрационный seed автоматически не загружается.

После создания администратора при необходимости добавьте восемь пробных событий командой `python3 deploy/seed-events.py --apply`. Команда публикует их от имени первого SUPER_ADMIN, поэтому сначала проверьте названия, сроки и правила в `deploy/seed-events.py` на соответствие событиям вашего офиса. Повторный запуск не создаёт дубликаты. Для настоящих событий используйте форму предложения в приложении и публикацию администратором.

## Обновление и копии

Перед обновлением выполните `deploy/backup.sh` и отдельно сохраните deploy/.env в защищённое хранилище. Дамп содержит учётные записи, профили, события и кошельки. Расписание и выгрузку за пределы VPS оператор настраивает при установке. Копия на том же диске не защищает от потери VPS.

Обновите файлы, повторите сборку и миграции. Изменение адресов backend API требует пересборки приложения. Ротация JWT_SECRET и паролей действующей базы требует согласованного изменения служб и БД.

## Перенос облачных данных

Текущая база содержит вымышленные аккаунты и события. Для переноса сначала приостановите запись, выполните pg_dump и сохраните действующие секреты. Восстановление выполняется в отдельную пустую базу с совместимыми ролями. После восстановления проверяются права, миграции, вход и журнал кошельков. Дамп не применяется автоматически к существующей базе VPS.

## Десктоп и обновления

Десктопный клиент Electron использует тот же HTTPS-сервер, учётные записи и базу данных, что и веб-версия. Адрес сервера можно поменять в меню приложения «ФОНГРОБ → Настройки». Сессия сохраняется средствами шифрования ОС. При недоступности сервера появляется экран повтора подключения. Отключение системных уведомлений доступно в настройках.

В корне проекта: `npm ci`, `npm run desktop:dev` для разработки и `npm run desktop:build:win` для сборки Windows NSIS. Установщик создаётся в `dist-desktop/`. Команда `npm run desktop:build:portable` создаёт переносимый Windows EXE без установки. Linux-сборка: `npm run desktop:build:linux`. Установщик пока не подписан сертификатом; для публичного распространения потребуется подпись кода. Автоматическая доставка обновлений пока не настроена, при обновлении выпустите новый установщик. Текущая линия опрашивает API каждые 15 секунд.

Сезоны закрывает сервис `season_worker` из Compose. Он также обновляет достижения по времени, например «Ветеран». После миграций запустите этот сервис; без него сезоны и зависящие от времени достижения будут закрываться с задержкой.
